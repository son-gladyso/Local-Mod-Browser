## 散らばった MOD を、使える個人カタログへ

Local MOD Browser は、Windows 向けのローカル MOD カタログブラウザー、資料編集環境、AI 連携プラットフォームです。新しいコンテンツをダウンロードするのではなく、自分が所有・管理している、または明確に利用許諾を得たディレクトリのメタデータを、検索、絞り込み、比較、お気に入り登録、編集、翻訳、継続的な保守ができるローカルシステムにまとめます。

次のような困りごとがある方に向いています。

- MOD が複数のドライブ、ゲーム、バックアップフォルダーに分散し、ファイルを探すのに時間がかかる。
- ダウンロードした MOD が何をするものか、何のために欲しかったのか思い出せない。カタログ内の概要、機能説明、タグからファイルと用途のつながりを確認したい。
- 同じ MOD の複数バージョンやコピーをすぐ比較できず、元のファイルを誤って上書きしたくない。
- お気に入り、翻訳の進捗、作者情報、ファイル一覧が別々にあり、再インストール後に復元しにくい。
- AI に整理を手伝ってほしいが、サービスからローカルパス、所蔵一覧、データベースを第三者へ送信してほしくない。外部 AI クライアントのデータ共有動作は、そのクライアントによります。
- 一括編集や翻訳が中断しても、中途半端なレコード、二重送信、説明できない状態を残したくない。

一連の作業をローカルで完結させます。

```text
ディレクトリのメタデータ → 索引・検索 → 詳細 / タグ / ファイル比較 → お気に入り・構成セット
                                              ↓
                              資料の修訂 / 翻訳タスク / 再開可能な一括処理
                                              ↓
                              Web、CLI、MCP が同じローカル API を共有
```

現在の公開ソースには、構成セットのメモと、MOD の `function`、`details`、`tags` などを編集する機能があります。MOD ごとに独立した「ダウンロード理由」メモ欄があるという意味ではありません。文脈の回復には既存情報または自分で補足した情報が必要で、記録されていない元の意図は自動復元されません。

### どんな人に向いていますか？

- 複数ゲーム、複数の MOD 入手元、長年の蓄積があるプレイヤー。
- MOD の資料を繰り返し探し、比較、翻訳、整理する制作者やメンテナー。
- 自分のコンピューター上のデータを自分で管理しながら AI を利用したい人。
- 「クリックして祈る」のでなく、再現・検証・復旧できる自動化を好む人。

### このツールではないもの

MOD 配布サイト、インストーラー、クラックツール、リモートホスティングサービスではありません。MOD の安全性、互換性、利用許諾も代わりに判断しません。すでに所有し、利用する権利がある資料を整理して、変更を見える形で制御しやすくします。MOD のダウンロード、再配布、インストール、実行は行いません。

## 利用できる機能

### 長く使い続けられる MOD ブラウザー

- ゲーム、キーワード、タグの組み合わせ、翻訳状態、作者、日付、ファイル情報で素早く絞り込み。
- 一覧、詳細、履歴を安定して行き来し、文脈を確かめるためにフォルダーへ戻る必要を減らします。
- 画像、作者の本文、ファイル一覧、参照元リンクを表示。MOD 名だけでなく、具体的なファイルのコピーを比較。
- 重要項目をお気に入り登録し、インポート・エクスポート可能な構成セットを保存。再インストールやディレクトリ移動後も作業を継続。
- 横長のデスクトップ画面にも狭い画面にも対応。複雑なフィルターを折りたたみ、重要な結果を優先表示。

### 資料の保守に向けた作業環境

- `apply` の前に `preview` で変更を確認し、誤編集と一括操作のリスクを減らします。
- 翻訳をフィールド・セグメント単位で管理。バッチ、進捗、品質チェック、停止・再開、冪等な再実行に対応。
- バックグラウンドタスクはリース、更新、引き継ぎ、イベントカーソルを備え、別の AI や開き直した画面から再開できます。
- 重要な書き込みには安定した冪等キーと正式な処理結果の受領記録があります。通信中断後は結果を確認してから再試行の要否を判断。
- SQLite の WAL と FULL 同期、復元ジャーナル、ペアのバックアップにより、資料の完全性を優先します。

### AI が適切に使えるローカルプラットフォーム

- Web、CLI、任意の MCP アダプターが同じ契約を共有し、AI が画面クリックを模倣する必要はありません。
- 検索、詳細、資料修訂、お気に入り、構成セット、翻訳、タスク管理を 70 の安定した操作で扱います。
- 5 つの決定的ワークフローが、検索→確認→変更→再読み取り→報告を段階的に案内。
- ローカル API は既定で `127.0.0.1` のみを待ち受けます。サービスは汎用モデルを呼び出さず、クラウドへ自動送信もしません。
- 例外発生時にクライアントへ返すのはリクエスト ID のみ。ローカル診断ログを分離し、パスやスタックトレースの漏えいを防ぎます。

## プライバシーと安全上の境界

Local MOD Browser の境界は明確です。

- **自分が提供したメタデータだけを索引化。** リポジトリにユーザーの元の MOD ライブラリ、アーカイブ、データベース、バックアップ、エクスポート、実行時トークンは含まれません。選別したユーザー提供スクリーンショットは独立した説明資料で、テストデータや配布コンテンツではありません。
- **MOD をダウンロード、再配布、インストール、実行しません。** 資料管理ツールであり、ダウンローダーやインストーラーではありません。
- **既定ではローカルのみで待ち受け。** `127.0.0.1` にバインドし、LAN や公開インターネット向けサービスとしては設計されていません。
- **第三者アカウントは必須ではありません。** 任意の MCP はローカルプロトコルの入口で、リモートモデルを自動呼び出ししません。外部 AI クライアントは読み取ったデータを提供元へ送る可能性があるため、接続前に設定と許可範囲を確認してください。
- **第三者データの利用許諾は利用者の責任です。** 各サイト・サービスの規約、API ポリシー、コンテンツライセンスを守ってください。

[セキュリティポリシー](../../SECURITY.md)、[貢献ガイド](../../CONTRIBUTING.md)、[第三者に関する告知](../../THIRD_PARTY_NOTICES.md)も参照してください。実行環境、データベース、トークン、診断ログ、エクスポート、テスト生成物の既定パスは `.gitignore` に含め、誤コミットの危険を減らしています。追跡済みファイル、強制追加したファイル、別の場所のデータは保護されません。コミット前にステージ済みの変更を確認してください。

## 対応環境

- Windows 10/11 x64。
- 固定ランタイム：CPython 3.13.15 x64、SQLite 3.53.4。
- 初回は固定ランタイムのダウンロードと検証にネット接続が必要です。ブートストラップスクリプトはシステムの Python で実行します。
- ランタイムの配布元、ハッシュ、ライセンスは [`runtime-lock.json`](../../runtime-lock.json) に記載。
- Linux と macOS は現在未対応です。コアサービスは Python 標準ライブラリを使い、追加のバックエンドフレームワークは不要です。

<a id="five-minute-quick-start"></a>
## 5 分で使い始める

### 1. コードを取得してローカル設定を用意する

```powershell
git clone https://github.com/son-gladyso/Local-Mod-Browser.git
cd Local-Mod-Browser
New-Item -ItemType Directory -Force data | Out-Null
Copy-Item config\sources.example.json data\sources.json
```

### 2. 固定ランタイムをインストールして起動する

```powershell
python tools\bootstrap_runtime.py
.\.runtime\python.exe -X utf8 launcher.py --no-browser
```

リポジトリ内の `启动MOD浏览器.cmd` をダブルクリックしても起動できます。ランチャーが表示するローカル URL を開くと、架空のデモカタログと空のライブラリの流れを確認できます。初回起動に実際の MOD ライブラリは不要です。

公開ソースを直接取得する場合は、[v2.5.2 Release](https://github.com/son-gladyso/Local-Mod-Browser/releases/tag/v2.5.2) の `Local-Mod-Browser-2.5.2-source.zip` を使ってください。同梱の `SHA256SUMS.txt` でアーカイブの完全性を検証できます。

### 3. 自分のカタログを接続する

Git の追跡対象外である `data\sources.json` を編集します。

```json
[
  {
    "key": "mygame",
    "title": "My Game",
    "root": "D:\\Mods\\My Game",
    "outputDir": "D:\\Mods\\My Game\\catalog"
  }
]
```

各 `outputDir` に `catalog-data.json` を置きます。相対パスは `sources.json` のあるディレクトリを基準に解決されます。`LOCAL_MOD_BROWSER_SOURCES` で別の設定ファイルも指定できます。詳しくは [`config/sources.example.json`](../../config/sources.example.json) と [`examples/demo-game/catalog-data.json`](../../examples/demo-game/catalog-data.json) を参照してください。

### 4. サービスとローカル API を確認する

```powershell
.\.runtime\python.exe -X utf8 ai.py doctor
.\.runtime\python.exe -X utf8 ai.py capabilities
.\.runtime\python.exe -X utf8 ai.py games
```

`/api/docs` で機械可読な契約を、`/api/health` でランタイム、データベース、サービスの状態を確認できます。

## 初回実行の成功をどう確認する？

自分のライブラリをインポートする前に、付属の架空レコードを使います。サービス起動→ローカル URL を開く→サンプルを検索→詳細を開く→一覧に戻る。この小さな流れで、ドライブ全体を整理する前に閲覧・検索を確認できます。

Windows 10/11 x64、ブートストラップスクリプトを動かせるシステム Python、初回ランタイム取得用のネット接続を用意してください。通常の利用に AI や MCP は不要です。開発者向けテスト依存関係は[貢献ガイド](../../CONTRIBUTING.md)にあります。

**成功の目安：** 架空カタログが表示され、検索・詳細を操作でき、`ai.py doctor` の結果を確認できることです。ページを開けただけで、自分のソース設定、復旧動作、全プラットフォーム操作の検証が終わったことにはなりません。

## よくある質問

**ダウンロード後、画像にあった大規模ライブラリがないのはなぜ？** ユーザー提供の実際の利用画面であり、データは配布されません。付属するのは架空の Demo レコード 8 件です。自分のソースは別途設定してください。

**ドライブ内のすべての MOD を自動走査して理解しますか？** いいえ。入口はソース設定と各 `outputDir` の `catalog-data.json` です。任意のフォルダーを万能に解釈するものではありません。[設定例](../../config/sources.example.json)とパス・メタデータを照合してください。

**なぜ MOD をダウンロードしたか思い出せますか？** 登録済みの概要、機能説明、タグから用途を見直せます。資料を編集し、構成セットのメモに予定を手動で書くこともできます。記録していない元の動機をファイルから推測はできません。この README は MOD ごとの独立したダウンロード理由欄を約束しません。

**一覧が空なのはなぜ？** `data\sources.json` が有効か、相対パスの基準となる設定ディレクトリはどこか、対象の `outputDir` に `catalog-data.json` があるかを確認し、[ユーザーガイド](../user-guide.md)に沿ってサービスを調べてください。私的なデータベースを Issue に投稿しないでください。

**閲覧には AI 接続が必要ですか？** 不要です。Web と CLI を直接利用できます。任意の MCP はローカルインターフェースで、自動的にクラウドモデルにつなぐスイッチではありません。選んだ外部クライアントには固有のデータ境界があります。

**実際の利用画面にあるダウンロードセンターは、公開版が MOD を取得できる証拠ですか？** いいえ。ユーザーのローカル画面ではダウンロード一覧が空で、Nexus は未接続です。公開版の説明は引き続き「ダウンロード、インストール、実行しない」です。

**他の機器やインターネットからアクセスできますか？** 既定では `127.0.0.1` のみです。LAN・公開サービスとして展開しないでください。Windows 以外も現在は未対応です。

### 変更する箇所からソースを読む

- 閲覧・操作：`static/` から始め、一覧、詳細、空・エラー状態、狭い画面での動作を確認。
- ソース・検索：`catalog.py` と設定例から始め、合成カタログで有効・無効な入力をテスト。
- プラットフォーム操作：`contracts.py`、`platform_api.py`、対応するテストを一緒に読み、HTTP、CLI、MCP を一致させます。
- 永続化・バックグラウンドタスク：まず[アーキテクチャガイド](../architecture.md)を読み、中断、再試行、復旧を網羅。速度のために耐久性を犠牲にしないでください。

コマンドと PR の要件は[貢献ガイド](../../CONTRIBUTING.md)、入門タスクは[ロードマップと貢献](#roadmap-and-contributing)にあります。

<a id="ai-and-cli"></a>
## AI と CLI

CLI はスクリプトや AI の安定した入口で、マウス操作の模倣は不要です。

```powershell
.\.runtime\python.exe -X utf8 ai.py tour
.\.runtime\python.exe -X utf8 ai.py capabilities
.\.runtime\python.exe -X utf8 ai.py games
.\.runtime\python.exe -X utf8 ai.py doctor
```

推奨する安全な作業手順：

1. 能力一覧とインターフェース説明を読み、現在の版で対応する操作を確認。
2. リソースを検索・読み取りしてから `preview` を送信。配列順序からファイル ID を推測しないでください。
3. プレビューのリソース ID、版、差分を確認し、安定した `idempotencyKey` で適用。
4. バックグラウンドタスクの実際の終端状態を待ち、業務データの再読み取りと正式な受領記録を確認。`queued` は完了ではありません。
5. 中断後は受領記録とイベントカーソルを確認してから、続行、引き継ぎ、再試行します。

[`docs/user-guide.md`](../user-guide.md)、[`docs/ai-platform-guide.md`](../ai-platform-guide.md)、[`docs/architecture.md`](../architecture.md)を参照してください。

## 検証と品質基準

起動できるだけでは完成とは見なしません。公開版には再現可能な合成受け入れテストがあります。

```powershell
# Python 回帰テスト
.\.runtime\python.exe -X utf8 -m unittest discover -s tests -v

# 起動・連携・契約
.\.runtime\python.exe -X utf8 tests\startup_acceptance.py
.\.runtime\python.exe -X utf8 tests\collaboration_acceptance.py
python -m pip install jsonschema==4.26.0
python -X utf8 tests\contract_audit.py --fixture

# フロントエンド構文
node --check static/app.js
node --check static/editor.js
node --check tests/browser.cjs
```

ブラウザーの受け入れテストには、別途 `npm install` と Playwright のブラウザーが必要です。Windows CI は固定ランタイムのインストール、Python 回帰、契約監査、JavaScript 構文チェックを自動実行します。[貢献ガイド](../../CONTRIBUTING.md)を参照してください。

## ロードマップと貢献

現在の公開版は `v2.5.2`、API 契約は `2.5.0` です。優先事項は次のとおりです。

- データ収集範囲を広げず、ローカルの資料整理を速く、確認しやすくする。
- API、CLI、MCP の動作を一致させ、失敗を説明・復旧できるようにする。
- 合成データと再現可能な受け入れテストで安全性を守り、私的な所蔵一覧を公開テストデータにしない。
- 明確なコンテンツ許諾と第三者規約の範囲でソースアダプターを拡張する。

最新の方向性は [`ROADMAP.md`](../../ROADMAP.md) にあります。文書、再現可能なテスト、アクセシビリティ、小さなソース設定の改善は初めての貢献に向いています。

Issue、文書の改善、Pull Request を歓迎します。先に [CONTRIBUTING.md](../../CONTRIBUTING.md) を読み、個人のパス、所蔵一覧、データベース、画像内のトークン、無許可の第三者コンテンツを提出しないでください。外部からの変更はレビューされ、`main` へのマージ前に CI、Code Owner の承認、議論の解決、プライバシーチェック、対象を絞ったテストが必要です。

実際の問題解決に役立ったなら、Star を付けたり、MOD フォルダーに困っている人に紹介したり、具体的な Issue を投稿してください。明確で再現可能なフィードバックは「よさそう」や曖昧な機能要望より役立ちます。採用された変更は公開履歴で確認できます。

### 小さな改善から始める

初参加なら、既存のタスクを選べます。

- [初回実行 FAQ（#3）](https://github.com/son-gladyso/Local-Mod-Browser/issues/3)：ランタイムの導入、ソース設定、カタログファイルの欠落に対する切り分けと確認手順を追加。
- [ソース設定の文書と検証（#2）](https://github.com/son-gladyso/Local-Mod-Browser/issues/2)：フィールドと相対パスを説明し、合成設定でエラーをテスト。
- [空・エラー状態のアクセシビリティ（#1）](https://github.com/son-gladyso/Local-Mod-Browser/issues/1)：キーボードとスクリーンリーダーの利用者にも次の操作が分かるようにする。

着手範囲を示す前に、Issue の最新の議論と状態を確認してください。小さな文書修正は直接 PR にできます。大きな機能、データモデル、ソースアダプターの変更は貢献ガイドに沿って先に相談してください。自分の MOD ライブラリを提供する必要はありません。
